# Translations

All maintained Chinese/English translation pairs live in these UTF-8 JSON files:

- `internal/i18n/locales/en-US.json`
- `internal/i18n/locales/zh-CN.json`

The shared `internal/i18n` package embeds these files with `go:embed` and parses them once at startup. Updating a bundled translation requires rebuilding the application. The executable works from any directory without copying locale files beside it, and rendering performs no JSON parsing or disk reads.

## Editing text

Use the same key in both language files. Keep keys stable when wording changes. New UI messages belong in `messages`; for example:

```json
"version.total": "%d versions total"
```

Read a message through the active UI language:

```go
label := a.L("version.total")
text := fmt.Sprintf(label, count)
```

Existing `a.tr().FieldName` calls read the `copy` section through the typed `Copy` structure. This structure contains field declarations only, not translation values. Changing existing text in either section needs no Go edit. A new typed field must also be declared in `internal/i18n/i18n_copy.go`; ordinary new messages do not need a struct change.

Preserve leading/trailing spaces and Go formatting placeholders such as `%s`, `%d`, `%.1f` and `%%`. Keep their types and order consistent between languages. Date layouts use Go's reference date (`Jan 02, 2006`). Counted messages use `.one` and `.other` keys, selected by `i18n.Plural`; translations contain the complete phrase instead of relying on English word replacements.

## Catalog sections

| Section | Contents |
| --- | --- |
| `code` | Canonical locale tag, matching the filename |
| `copy` | Existing typed UI labels and descriptions |
| `messages` | Keyed labels, format strings, status names, task titles and crash explanations |
| `categories` | Provider category slugs/names, matched without case sensitivity |
| `jobMessages` | Source progress prefixes and their display translations |
| `phases` | Source Java scan phases and their display translations |
| `numberUnits` | Descending numeric thresholds and suffixes for download counts |

Missing Chinese entries inherit the corresponding English entry. An explicit empty string is intentional and is preserved. Unknown message keys display the key; unknown categories, progress messages and scan phases retain their original text. Progress matching uses the longest known prefix first, preserving dynamic counts and filenames.

System language detection, manual selection and command-line overrides keep their existing behavior. Display text resolves when rendered, so task titles and labels follow language switches. Selector normalization recognizes labels from both JSON catalogs; legacy input aliases remain accepted for compatibility.

## Validation

Run `go test ./internal/i18n` for JSON schema, duplicate keys, translation coverage, placeholder consistency, fallback behavior and references from Go code. Run `make check` for UI/launcher regressions, formatting, architecture and static analysis in both development and release modes.

New translated UI text must use a JSON key. The CJK regression baseline is limited to legacy input matching, diagnostics and stable accessibility/test identifiers; it is not a place to add new translation pairs.
