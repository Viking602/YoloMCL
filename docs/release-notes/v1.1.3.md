YoloMCL 1.1.3 improves Windows startup rendering and updates MyGo to 0.7.4.

## Fixes

- Enable interface hardware acceleration on first launch and when restoring default settings, addressing the blank startup window reported in [#2](https://github.com/Viking602/YoloMCL/issues/2).
- Retain MyGo's automatic software fallback when GPU rendering is unavailable. Existing renderer preferences and explicit `MYGO_GPU` overrides remain respected; saved configurations now record disabled choices explicitly.
- Upgrade MyGo from 0.5.5 to 0.7.4, including its Windows first-frame display improvements.
- Update the English and Chinese settings descriptions to explain the new default and restart requirement.

## Validation

- Pass the full development and release test suites, static analysis, and cross-builds for Windows, macOS and Linux on amd64 and arm64.
- Verify first-launch GPU rendering, software rendering after disabling acceleration and restarting, and restoring defaults on Windows. The local build was also confirmed by the maintainer.
- Pass MyGo's GPU failure and software fallback regression tests.
- Keep the signed-update integration test compatible with MyGo's deferred application-bundle replacement on macOS, while still rejecting tampered archives and verifying the installed contents.

## Updating

Existing official installations can update from Settings. Updates remain optional, and upgrading preserves existing renderer preferences. To enable hardware acceleration for an existing Windows configuration, turn it on in Settings and restart the launcher.

For manual installation, download the archive matching your operating system and processor: `.zip` for Windows, or `.tar.gz` for macOS and Linux. Extract the complete archive before launching. `amd64` is Intel/AMD x64; `arm64` includes Apple Silicon.
