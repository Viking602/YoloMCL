# 等结果优化与延迟分析

目标是保留版本算法、浮点舍入和群系等距选择，只减少重复计算、分配与显示等待。最终数字和原始记录见 [BENCHMARKS.md](BENCHMARKS.md)。原版参照 [C cubiomes](https://github.com/Cubitect/cubiomes/tree/e61f90580cbdd883214a8054670dacae655e59c0)，26.x 另用固定校验值的官方 Java 运行结果；模组直接依据公开源码和对应版本资源验证。

## 已实施的调整

| 瓶颈 | 调整 | 为什么不改变结果 |
| --- | --- | --- |
| 切换种子重复解码 JSON、建立规则图和参数树 | 最多 16 项的编译缓存；`WithSeed` 仅重建噪声；内置注册表只解码一次 | 图和参数树不可变；缓存键覆盖参与编译的注册表内容；更换种子独立绑定随机序列 |
| 末地每次扫描 25×25 邻域和重复计算同一岛屿 | 64 行滑动坐标缓存、占用位图、数值群系 ID；旧版按最小岛屿因子作距离剪枝 | 只跳过确定为空或无法影响分类的候选；仍使用对应版本的浮点运算和坐标语义 |
| 末地初始化跳过 17,292 次 LCG 输出 | 仿射变换平方求幂，复杂度由 O(n) 降为 O(log n) | 在模 2^48 环上合成同一递推式 |
| 气候树计算大量最终不会胜出的距离 | 累加平方距离达到当前最优值即停止；零距离直接返回；避免复制节点范围数组 | 每项非负；仍使用严格小于比较、原有兄弟顺序和前一叶节点，不更换树形 |
| 历史缩放图层重复索引、写回和坐标换算 | 按行访问父图层与输出，先在局部变量完成计算；quart 输出直接映射 | 随机调用顺序和整数算法不变 |
| mcl 每个像素查字符串颜色与图例哈希 | 每个生成器预建数值调色板，位图记录已出现的群系 | ID 到名称和颜色的映射不变；调色板按有效快照构建 |
| 整个视口计算完成才能显示 | 中央瓦片优先；第一块和每四块提交不可变部分图像，最后提交完整图像 | 改变显示顺序，瓦片仍完整计算；结构标记在最终帧绘制，取消和代次检查保留 |

优化前 CPU profile 显示：现代主世界树距离约占 38% 的 flat CPU，Perlin 调用链约占 43% 的累计 CPU；末地高度计算约占 74% 的 flat CPU；历史图层的缩放、河流和平滑循环为主要开销。初始化则集中在 JSON、对象分配和 GC。比例来自各自独立负载，不能跨 profile 相加，累计比例之间也有重叠。

`New` 和 `Compile` 的换种子基准是规则已加载后的重复调用。第一次进入进程仍需解压、解码、验证和编译；16 项缓存被逐出后也需重新编译。热采样零分配不等于生成器、工作区或 mcl 图像没有内存成本。渐进绘制需要复制部分帧，换取更早显示；只命中缓存的视口直接提交一次完整帧。

## 仍值得做的优化

1. **噪声内核专用化。** 现代主世界剩余成本主要在 Perlin 和密度节点分发。可把已编译图降低为紧凑指令、合并坐标变换，或为常见原版图生成专用执行器。必须保留每个版本的求值与舍入顺序；26.3 的 float 路径不能套用旧版 double 路径。
2. **受控的瓦片并行。** 纯 Go 的不可变生成器允许每个 worker 独立 Sampler。多核能降低完整视口延迟，但增加 CPU、工作区内存与过期任务开销；需要用实际拖动轨迹和帧延迟评估，并保留取消。目前仍保持一个按需工作线程。
3. **历史图层融合。** 旧版仍有多层中间矩形、随机状态和较多边界访问。可对固定组合融合缩放/平滑/河流，减少遍历与缓冲区；必须验证负坐标、特殊版本分支及随机调用次数。
4. **构建期生成原版规则。** 预编译密度图和参数树可进一步降低首次打开的延迟；自定义数据包仍保留通用编译器。生成文件必须带版本、输入哈希和可复现脚本。
5. **模组区域图层融合。** TerraBlender 已使用原生 Go 的加权选择、缩放和平滑图层，按采样器缓存中间结果。可以进一步测量区域边界密集区，尝试矩形批量生成，保留原有随机调用及相同值的选择顺序。

不采用降低采样精度、近似噪声、fast-math、任意重排浮点累加、按命中概率重排群系树或改变等距策略。这些办法可能更快，但会在边界格改变结果。26.3 的正确树分支数是 19，旧版分别使用对应版本的 10 或 6；不能为了性能统一替换。

## 新版与模组边界

[mcseedmap.net](https://mcseedmap.net/) 用作功能和覆盖范围参考。这里实现的是固定 Y 的群系切片，尚未实现它的地表高度着色或完整结构定位。

JSON 数据包由 Go 编译其有效注册表，支持版本化 pack metadata、覆盖顺序和 overlays。注入式模组通过按公开源码实现的原生适配器，扩展同一个生成引擎；TerraBlender/BOP 共用区域选择、气候树和末地计算。完整模组文件哈希、配置、选中存档和数据包次序进入快照；切换种子复用不可变规则。具体版本、逐格验证和性能见 [模组报告](../docs/seed-map-mods.md)。

群系一致不表示生成方块、结构生成、已保存区块或升级混合区一致。生产代码不依赖 JVM、HTTP 或进程通信；独立参考程序位于项目外，项目中只保存参考数据、来源记录和 Go 回归测试。
